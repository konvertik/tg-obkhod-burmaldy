# MTProto Proxy Manager

Android-приложение для поиска, проверки и передачи MTProto-прокси в Telegram.

## Что делает

- Загружает списки прокси из настраиваемых публичных источников (по умолчанию два, см. ниже).
- Извлекает только ссылки `t.me/proxy`, `telegram.me/proxy` и `tg://proxy`, проверяет каждую (адрес, порт, hex-secret).
- Проверяет доступность серверов TCP-подключением, показывает пинг и статус.
- Сортирует по пингу, доступности или стране; группирует по стране.
- Автоматически выбирает лучший доступный прокси (избранные получают небольшой бонус).
- Добавление вручную по ссылке, избранное, копирование ссылки.
- Фоновое обновление списков (по интервалу из настроек) и перепроверка недоступных серверов примерно каждые 15 минут при наличии сети.
- Светлая, тёмная и системная тема. Интерфейс полностью на русском.

## Чего приложение НЕ делает

- Не создаёт VPN-подключение и не использует `VpnService`.
- Не перехватывает и не проксирует трафик устройства.
- Не отправляет данные протокола MTProto при проверке: только TCP-соединение.
- Не показывает рекламу, подписки и уведомления.
- **Не подтверждает подключение к Telegram.** Ссылка передаётся в Telegram через официальный deep link `tg://proxy`. Telegram не возвращает результат, поэтому после передачи пользователь подтверждает включение прокси в самом Telegram.
- Пинг означает только то, что сервер принимает TCP-соединения. Это не гарантирует работу прокси.
- Не выдумывает серверы: если источники недоступны, список остаётся пустым или прежним, а в настройках показывается причина ошибки.

## Источники по умолчанию

Задаются в `app/src/main/java/ru/mtproxymanager/data/SettingsStore.kt` (`DEFAULT_SOURCES`) и меняются в приложении (Настройки → Источники прокси):

- `https://raw.githubusercontent.com/0xRadikal/Free-Telegram-Proxy/main/top100.txt` — 100 прокси, отобранных по проверкам до дата-центров Telegram; проект прямо ориентирован на сети с блокировками.
- `https://raw.githubusercontent.com/0xRadikal/Free-Telegram-Proxy/main/faketls/tme.txt` — только FakeTLS-прокси (секрет с префиксом `ee`).

Для обхода блокировок в РФ включён приоритет FakeTLS (Настройки → Обход блокировок). Автовыбор предпочитает такие прокси.

## Как проверяется прокси

1. **TCP-пинг** — открывается соединение с сервером, замеряется время.
2. **Проверка протокола** — прокси считается рабочим, только если он реально пересылает запрос до дата-центра Telegram:
   - MTProto (`dd`, обычный secret): отправляется запрос `req_pq_multi` через прокси, и должен прийти ответ с нашим nonce.
   - MTProto FakeTLS (`ee`): сначала TLS-подобное рукопожатие с HMAC-подписью по секрету, затем тот же запрос.
   - SOCKS5: рукопожатие, аутентификация (если задана) и CONNECT до дата-центра Telegram.
3. Статусы: **Работает** (протокол подтверждён), **TCP доступен, протокол не подтверждён** (порт открыт, но пересылка не подтверждена), **Недоступен**.

Автовыбор берёт только прокси со статусом «Работает».

Результаты проверки на тестовой выборке (с ПК, одна сессия): dd/обычные MTProto — 25 из 40 подтвердились; FakeTLS (`ee`) — 2 из 40. Многие FakeTLS-серверы в списках мёртвые или ограничивают трафик. Полная поддержка FakeTLS-рукопожатия ещё требует доработки.

SOCKS5-прокси передаются через официальную ссылку `tg://socks`. Встроенных списков SOCKS5 нет: их нужно добавить в источники самостоятельно. VPN и перехват трафика приложение не делает.

Ограничение: проверка пингом — это TCP-подключение. Прокси может принимать соединение и всё равно не работать, если провайдер блокирует протокол. Реальную работоспособность видно только после подключения в Telegram. Списки сторонние и быстро меняются.

Это сторонние списки. Приложение не доверяет их содержимому: невалидные ссылки отбрасываются, размер ответа ограничен 2 МБ, таймауты заданы. Источники обязательно должны использовать `https://`.

## Требования

- Android 8.0 (API 26) и выше.
- Для сборки: JDK 17, Android SDK (platform 35, build-tools 35.0.0). Gradle wrapper входит в проект.

## Сборка

```powershell
# Windows, из корня проекта
$env:JAVA_HOME="путь\к\jdk17"
.\gradlew.bat assembleDebug          # отладочный APK
.\gradlew.bat testDebugUnitTest      # unit-тесты парсера
.\gradlew.bat assembleRelease        # release APK
```

Файлы APK:
- `app/build/outputs/apk/debug/app-debug.apk`
- `app/build/outputs/apk/release/app-release.apk`

## CI и релизы

GitHub Actions (`.github/workflows/android.yml`) на каждый push и pull request запускает unit-тесты и собирает debug APK (он доступен в артефактах запуска).

Чтобы опубликовать релиз с APK, создайте тег:

```bash
git tag v1.0.0
git push origin v1.0.0
```

Release-APK в CI подписывается отладочным ключом. Для публичного релиза задайте собственный ключ через переменные из раздела ниже и добавьте их в секреты репозитория.

## Установка на телефон

1. Скопируйте APK на телефон (USB, облако или любой файловый обмен).
2. Откройте файл на телефоне. Если Android запросит разрешение, разрешите установку из этого источника.
3. Запустите «MTProto Proxy Manager». При первом запуске приложение само загрузит списки.
4. Выберите прокси и нажмите «Подключиться». Telegram откроется с запросом на включение прокси. Подтвердите его в Telegram.

Установка через ADB:

```powershell
adb install -r app\build\outputs\apk\debug\app-debug.apk
```

## Подпись релиза для публикации

Без переменных окружения release-сборка подписывается отладочным ключом. Это подходит только для личного использования. Для публикации создайте собственный ключ и передайте его через переменные:

```powershell
keytool -genkeypair -v -keystore C:\keys\mtproxy-release.jks -alias mtproxy -keyalg RSA -keysize 4096 -validity 10000

$env:MTPROXY_KEYSTORE_PATH="C:\keys\mtproxy-release.jks"
$env:MTPROXY_STORE_PASSWORD="..."
$env:MTPROXY_KEY_ALIAS="mtproxy"
$env:MTPROXY_KEY_PASSWORD="..."
.\gradlew.bat bundleRelease
```

Файл ключа и пароли не добавляйте в репозиторий (`.gitignore` уже исключает `*.jks` и `*.keystore`).

Перед публикацией в Google Play проверьте:
- `applicationId` (`ru.mtproxymanager`) и `versionCode`/`versionName` в `app/build.gradle.kts`;
- политику Google Play о VPN-приложениях: приложение не является VPN, но в описании это нужно указать явно;
- соответствие источников правилам магазина и законодательству вашей страны.

## Ограничения

- Страна определяется только если источник её указывает. Иначе прокси попадает в группу «Неизвестно». Определение по IP (GeoIP) не подключено, чтобы не отправлять IP-адреса серверам третьих лиц.
- Поддерживаются только hex-secret (`dd`, `ee` и обычные). Base64-варианты secret отклоняются.
- Ссылки из источников могут устаревать. Недоступные прокси остаются в списке и помечаются, пока не будут удалены при следующем обновлении источника (избранное и добавленные вручную не удаляются).
